# Headlines and copy

## The job of a headline

A screenshot headline names what the user gets from the screen below it, in words the screen can't say
on its own. It must be true for the current build.

## Rules

- **One idea per shot.** If you need "and", it's two shots.
- **Short.** Phone: 2–6 words for the main line, optional sub-line ≤ ~10 words. Google Play suggests text
  covers no more than ~20% of the image.
- **Specific over generic.** "Resume any episode on your TV" beats "Seamless entertainment".
- **Verbs and nouns from the app.** Use the app's own feature names when users will see them in the UI.
- **Proof on screen.** The screenshot directly under the headline must show the claim.
- **No unsupported claims**: no "#1", "best", "fastest", "award-winning", "free" (unless verifiably free
  with no paywall), "Sale", ratings, user counts, testimonials, "Download now"-style calls to action.
- **No repeated wording** across the set; vary sentence shape (imperative, noun phrase, outcome).
- **Readable small.** Check the store-scale contact sheet: if you can't read it at ~180 px tall, cut words
  or enlarge.
- **Localize** headlines and screenshots together; UI language and caption language must match.
- **Alt text** (Google Play): ≤ 140 characters per image, describe what's shown, don't start with "Image of".

## First three shots

They are what most people see in search results and the top of the listing.
1. Shot 1: the core promise — what the app is for — with the screen that proves it. Not a splash, login,
   onboarding or logo slide.
2. Shots 2–3: the strongest differentiators, the things competitors don't show.
3. Later shots: supporting features, settings that matter (offline, privacy, accessibility), platform
   reach (e.g. "Also on your TV" only if it ships there).

## Process

1. List real features from project-profile.md with evidence.
2. Rank by user value and distinctiveness.
3. Pair each with its most visual screen.
4. Write 2–3 headline options per shot; pick for clarity, then voice.
5. Read the set aloud in order: it should tell a story without repeating itself.
6. Re-verify every claim against code/screens.

## Voice

Match the app's own UI copy tone (formal, playful, terse). Sentence case unless the brand clearly uses
title case or all caps. Avoid exclamation marks unless the brand uses them.

## Red flags

"Unleash", "Elevate", "Seamless", "Revolutionary", "Next-level", "All-in-one" (unless literally true and
specific), "Your ultimate …", "Experience the …", "Like never before".
